# 技能沉淀规则

## 1. 目的与范围

本规则约束"什么时候把一套流程固化为本项目技能、怎么固化、怎么维护"。

- 技能正文放 `../skills/<name>/SKILL.md`，结构与索引约定见 `../skills/README.md`。
- 本规则只管**本项目专用**技能：依赖本项目的目录、接口、表、命令、约定或踩坑经验。
- 通用能力（换项目也能原样用）不放本项目技能库，放全局技能目录；本项目最多在 `rules/` 里写一句"用哪个通用技能"。

## 2. 沉淀判据（满足全部才沉淀）

1. **重复验证**：同一套流程已在本项目完整执行 **≥ 3 次**（可跨会话、跨 Agent、跨执行人）。
2. **形态稳定**：每次只是参数或输入不同，步骤、输入输出形态、判断条件基本一致。
3. **项目特有**：流程里包含本项目特有的路径、字段、接口、校验或已知坑，不是通用常识。
4. **有沉淀收益**：不沉淀就会反复解释、反复试错，或换人接手必然踩坑。

达到门槛即视为**必须沉淀**，在本次任务结束前完成，不需要等用户主动要求；用户明确拒绝时，在 `handoffs/` 记录原因。

例外：高风险且不可重试的流程（如发布、数据修复）执行 **2 次**后即可提前沉淀，并在 `skills/README.md` 索引的「沉淀依据」列注明原因。

## 3. 不沉淀的情形

- 只跑过 1–2 次，尚不稳定 → 先记在 `dev-plans/` 或 `handoffs/` 观察。
- 只是"必须 / 不要 / 优先"的约束 → 写 `rules/`，不要包装成技能。
- 只是系统现状、接口契约、链路事实 → 写 `mechanisms/`。
- 每次步骤都不一样，或依赖临场判断 → 先别固化，继续观察。
- 一次性任务、临时脚本、手工救火命令 → 放项目自己的脚本目录，不进技能库。
- 已有同类技能 → 更新原技能，不新建第二个。

## 4. 项目技能与全局技能的边界

用一个问题判定：**把这条技能搬到另一个项目，还需要改吗？**

- 需要改（依赖本项目任何具体信息）→ 本项目 `skills/`。
- 不需要改，可原样复用 → 全局技能；本项目只在规则里登记"何时调用它"。

不允许把通用技能复制一份放进本项目，也不允许把项目专用技能放进全局目录。

## 5. 沉淀流程（五步）

1. **识别与去重**：先读 `../skills/README.md` 索引，确认没有同类技能；有则定位到更新，而不是新建。
2. **提炼**：把已成功跑通的流程拆成「适用场景 → 前置检查 → 执行步骤 → 产出 → 边界与禁止 → 验证方式 → 配套规则」，删掉一次性参数、临时路径和会话上下文。
3. **写文件**：`skills/<name>/SKILL.md`，`name` 与目录同名，`description` 写清触发词与禁用场景；需要脚本或模板时放同目录 `scripts/`、`templates/`。
4. **双向登记**：在 `skills/README.md` 索引登记（含沉淀依据），并在触发它的规则文件补「配套技能」段（五列：技能 / 何时使用 / 何时不要用 / 怎么用 / 关联章节）。
5. **验证**：换一个新会话，只给 `SKILL.md` 和必要输入，独立执行一次；跑不通就改技能，不改规则。

## 6. 固化门槛（可验收）

技能文档必须同时满足：

- 另一个 Agent 在**不询问任何人**的情况下能按文档执行完。
- 每一步都有明确的输入、输出和判断条件。
- 有失败时的停止条件或回退方式，不靠"看着办"。
- 不依赖当前会话上下文、临时目录、个人记忆或未提交的分支。
- 至少有一次由未参与沉淀的会话/人按文档成功执行。

## 7. 使用、维护与废弃

- **使用**：任务命中规则中的「配套技能」标注时才加载；未登记的技能不主动加载。
- **迭代**：每次使用发现问题，先改 `SKILL.md`；触发条件变了再同步改规则侧「配套技能」表与索引。
- **纠偏**：连续 3 次使用都需要人工纠正 → 该技能不合格，重写或删除。
- **废弃**：流程被工具或脚本替代时，删除技能目录，并清理规则侧引用与索引，不留孤儿。
- **冲突**：技能内容与本规则或 `rules/` 冲突时，以本规则和 `rules/` 为准。

## 8. 禁止事项

- 不把一次性命令、临时救火步骤写成技能。
- 不在技能里复制 `rules/`、`mechanisms/` 的正文，只引用。
- 不建没有规则引用的孤儿技能，也不留已废弃技能的索引。
- 不让技能绕过规则中的禁止项、校验步骤和优先级。
- 不为"看起来完整"预置技能；初始化时 `skills/` 只有 README。
