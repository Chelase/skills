# 内网 → 公网端口映射（多层嵌套 NAT）

> **TL;DR** — 先把「几层 NAT、每层的目的 IP」列清楚，再逐层加同名端口规则，每加一层立刻实测，最后从公网验业务内容（不能只看端口通）。

## 什么时候用它 / 什么时候不用

- **用它**：内网服务需要从公网访问；绑了域名但外网打不开；要把某个内网端口暴露出去。
- **不用**：只是想在**同一内网**里访问（不需要 NAT 规则）；内网服务之间的互访（用 hosts 或直连即可）；需要代理到外部目标（本技能是"内网出公网"，不是"公网进内网"的隧道）。

## 核心原则

1. **有几层 NAT 就配几层，缺一层必然不通。** 只配最外层等于没配。
2. **端口逐跳对齐。** 每层的目的 IP 是**下一层的 WAN 口地址**，不是最终服务器地址。
3. **每加一个端口 = N 条规则**（每层各一条），不要只配一层就宣布完成。
4. **先查再改，每层改完立刻实测该层。** 不要攒到最后一起验。
5. **端口通 ≠ 服务通。** 最后必须从公网验业务内容（标题/响应体），端口能连上但服务没起是最常见的误判。

## 一、先建立拓扑（不要跳过）

配置前必须把这张表填满。**每层的「下一跳目的 IP」是从下一台设备的 WAN 口 IP 抄来的，不是猜的。**

| 层 | 设备 | WAN 口 IP | 管理入口 | 下一跳目的 IP |
|---|---|---|---|---|
| L1 | | | | |
| L2 | | | | |
| L3 | | | | |
| L4 | 服务器/被暴露的服务 | | | — |

收集方式：

- **看路由器管理页的 WAN 口 IP**（最可靠）。
- **看上一层设备上已配的转发规则**，已有规则的「内部服务器 IP」就是下一层的 WAN IP。
- **命令行查**：`ip -4 addr show`、`ip route`。

> **同段冲突警告**：多层家庭网络里，不同层的 LAN 常落在同一网段且网关 IP 相同（都是 `192.168.1.1` 这类默认值）。此时从内网访问该网关永远命中离你最近的那台，不是最外层。要访问最外层管理页，必须从它下级设备所在的网段访问。

## 二、准备配置清单

用 `config/nat-port-forward.config.example.json` 作为模板，复制成 `config/nat-port-forward.config.json`（真实配置不入库）：

```json
{
  "publicIp": "203.0.113.10",
  "server": { "sshAlias": "web-server", "internalIp": "192.168.30.104" },
  "layers": [
    {
      "id": "L1",
      "name": "最外层路由器",
      "model": "<路由器型号>",
      "adminUrl": "http://203.0.113.10:<管理端口>",
      "username": "admin",
      "password": "CHANGE_ME",
      "nextHopIp": "192.168.10.3"
    },
    { "id": "L2", "name": "二层路由", "model": "<路由器型号>", "adminUrl": "http://192.168.20.1", "password": "CHANGE_ME", "nextHopIp": "192.168.20.89" }
  ],
  "ports": [
    { "name": "web", "external": 10080, "internal": 80, "targetIp": "192.168.30.104", "note": "站点 HTTP" }
  ]
}
```

`model` 只作为后台记录用，不影响操作流程。

**规划端口时的硬规则**：

- **不要占用路由器的管理端口**（某台设备的管理页已迁到高位端口，就不要再把 80 抢回来）。
- **80/443 可能是运营商封禁的**。家用宽带常见 ISP 在 BRAS 层按**目的端口号**丢弃入站 80/443。此时把服务改映射到任意高位端口（10080 / 18081 / 18083…）即可绕过——**封的是端口号，不是服务**。
- **不要把数据库端口（3306/6379）映射到公网。** 运维走 SSH 隧道。
- 外部端口与内部端口**不必相同**，但**逐层递减只允许发生在最后一跳**，中间层用同名最省事、最好排查。

## 三、配置流程

### Step 0 — 确认服务在监听

```bash
ssh <server-alias> "ss -tlnp | grep ':<内部端口> '"
```

没有监听就先解决服务。**没监听时配完表现为「连接被拒绝 RST」而不是超时**，容易误判成 NAT 没配对。

### Step 1 — 从最内层开始配（离服务器最近的那层）

顺序：**内层 → 外层**。这样内层配完就能验证，问题定位范围最小。

每层操作：
1. 浏览器打开该层管理入口并登录。
2. 找到「虚拟服务器」/「端口映射」/「NAT 服务」页面。
3. 按 `references/router-admin-ui.md` 的通用方法新增一条规则。
4. **立刻验证这一层**（见 Step 4 的逐层验证）。

### Step 2 — 逐层往外配

重复 Step 1，直到最外层。

### Step 3 — 特殊场景：HTTPS

运营商封 80/443 时，HTTPS 有两种走法：

**A. 高位端口自带 TLS（推荐）**
服务器 nginx 在该内部端口上 `listen <端口> ssl;` 并挂证书，外网用 `https://域名:<端口>/` 访问。

> **同端口不能同时提供 HTTP 和 HTTPS。** `listen <端口> ssl;` 之后明文访问会返回 400。要两者兼有需另开端口或用 `stream` + `ssl_preread` 做协议分流。
>
> **不要加 `error_page 497 https://$host$request_uri;`**。497 = "明文请求打到 SSL 端口"，该行把它 301 到不带端口的 443，443 若被封则表现为 HTTP 也打不开。
>
> **Web 面板的「强制 HTTPS」开关不要开**。它 301 到默认 443，等于废掉 HTTP 入口。只开「SSL」不开「强制 HTTPS」。

**B. 前置 CDN/隧道**
Cloudflare Tunnel、frp 等，出站建立连接，天然绕过入站封禁，且能正常用 443。

**证书申请**：入站 80/443 不可达时，HTTP-01 校验（文件验证）必失败，必须用 **DNS-01 校验**（域名 DNS 服务商 API，或手动加 TXT 记录）。

**后端不需要配 SSL**：TLS 在 nginx 终结，nginx 到后端 `127.0.0.1:<port>` 是同机明文回环，改成 https 反而失败。

### Step 4 — 逐层验证

```bash
# 从服务器打下一层设备的 WAN 口（验证内层规则）
ssh <server-alias> "timeout 8 bash -c '</dev/tcp/<下一层WAN_IP>/<外部端口>'" && echo OK || echo FAIL
```

```powershell
# 公网层
Test-NetConnection -ComputerName <公网IP> -Port <外部端口> -InformationLevel Quiet
```

**全部通过后还要验业务内容**（端口通不代表服务对）：

```powershell
curl.exe -sk -o NUL -w "%{http_code}`n" https://<域名>:<端口>/
curl.exe -sk -o NUL -w "%{http_code}`n" https://<域名>:<端口>/<健康检查路径>
```

服务端日志也要看，确认请求真的到了后端（而不是被上游网关代答）。

## 四、故障排查对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 公网端口**超时** | 某层缺规则，或中间层路由不通 | 从内往外逐层 `/dev/tcp` 打，定位断在哪一跳 |
| 公网端口**连接被拒绝 RST** | 包到了但目标没监听 | 查服务器 `ss -tlnp`，服务没起 |
| 端口通但**页面空白/404** | nginx 站点没绑该端口，或域名/站点不匹配 | 查 vhost 的 `listen` 与 `server_name` |
| 端口通但**接口 404** | nginx 的伪静态/反代 include 被注释或路径写错 | 查站点 vhost 的 `#REWRITE-START` 段 |
| **HTTP 突然全挂** | 被「强制 HTTPS」或 `error_page 497` 劫持到 443 | 关掉强制 HTTPS；删掉 `error_page 497` |
| **HTTPS 握手失败** | 该端口的 nginx 没加 `ssl` | `listen <端口> ssl;` + 挂证书 |
| 502 且**服务器 error.log 有记录** | 后端挂了/重启中 | 查后端进程与端口 |
| 502 且**服务器无任何日志** | 不是你的服务器返回的，是中间网关/运营商 WAF | 换外部网络验证；核对运营商封禁情况 |
| 访问网关 IP 打不开预期页面 | 同段冲突，命中了内层设备 | 从外层设备下级网段访问 |
| 提交规则后表格出现 `--` 空行 | 下拉框只改了隐藏 input 的 value | 必须真正点选选项，等校验错误消失 |
| 证书申请一直失败 | 用了文件验证（依赖公网 80） | 改 DNS-01 验证 |
| 续期后配置被改回 | 面板重新部署时重写 vhost | 复核 `listen`/`ssl`/`error_page 497`，必要时锁定文件 |

## 五、验收清单

- [ ] 每层都有一条同名端口规则，逐层 `/dev/tcp` 实测通过
- [ ] `Test-NetConnection <公网IP> -Port <端口>` = True
- [ ] 公网 `curl` 拿到**正确业务内容**（不是只看状态码）
- [ ] 前端接口路径实测 200（不只是首页 200）
- [ ] 原有端口未被破坏（管理端口、SSH、面板端口仍通）
- [ ] 各层管理页仍可登录
- [ ] 未意外暴露 3306 / 6379 等敏感端口

## 七、边界

- 本技能只管 **NAT 规则**。nginx 站点配置、证书签发、CDN 接入只给到"该做什么、为什么"，具体站点改造由项目自身规则决定。
- 不要修改各层路由器的**管理端口配置**（防止抢占管理页）。
- 不要动已有规则，只加不改的端口，保持现状。
- 一次只加一个端口并验证通过，再加下一个；批量加完最后一起验，失败时无法定位是哪一层断的。
